### 4.2 ⚠ 混合流算法**根本没被用上**

工程文件里 **8 条线全是 `hydro1d_regime = "subcritical"`**。
新写的两遍法只在 `regime in ("mixed","auto")` 时执行 → **这段代码在当前工程里一行没跑**。

强制切成 `auto` 后（内存里改，未动文件）：

| 线 | subcritical NaN | auto NaN | 改善 |
|---|---|---|---|
| XLC4 / BJC1 / MFG1 / QF1 / DHC1 | 2 | 1 | +1 |
| TYSQ1 | 7/8 | 6/8 | +1 |
| CX1 / AL1 | 0 | 0 | 0 |

**只多救回 1 个断面，中间仍留一个"洞"。**
原因：两遍法各自推到一个失败点就断，**单点失败会让该遍后续全部 NaN**（NaN 级联），
所以最终是「下游一段 + 上游一段 + 中间空洞」。

> **结论**：新能力默认关闭（`model.py` 里 `hydro1d_regime` 默认 `"subcritical"`），

## 五、根因复核：**7/23 段缓流方程真的无解**

我把 23 个河段逐段细扫（1 cm 步长）求能量方程残差的最小值：

```
f(Z_up) = H_up − (H_down + hf + he)
f_min > tol(1e-4)  ⇒  该段无解
```

**23 段里有 7 段 f_min > 0，而且不是容差问题**——
DHC1-1→2 的 f_min = **+0.8716 m**，比容差大 4 个数量级。**真无解。**

### 5.1 设计水位之间**互相不自洽**（这是根因）

`design_level` 是怎么来的：拿设计流量在该断面**自己的** H~Q 曲线上反查
（`solver.py:52`），而 H~Q 曲线用**该断面自己的**比降参数。
⇒ **每个断面的设计水位 = 该断面在自身几何/糙率下的"正常水深"水位（均匀流假设）。**

问题在于：**相邻断面的正常水深互不构成一条满足能量方程的水面线。**
实测逐段的水头收支（设计水位处）：

| 段 | 需涨水 | 可用水头损失 | 差额 | 判定 |
|---|---|---|---|---|
| DHC1-1→2 | +2.237 | 0.707 | **−1.648** | **无解** |
| DHC1-2→3 | +1.701 | 0.566 | **−1.229** | **无解** |
| TYSQ1-2→3 | +3.508 | 0.013 | **−2.928** | **无解** |
| TYSQ1-6→7 | +2.981 | 0.147 | **−1.891** | **无解** |
| XLC4-2→1 | +4.269 | 1.939 | **−0.993** | **无解** |
| BJC1-1→2 | +0.880 | 0.499 | **−0.486** | **无解** |
| —— 对照：可解的段 —— | | | | |
| CX1-2→3 | +0.537 | 0.273 | −0.227 | 可解 |
| MFG1-2→3 | +0.658 | 1.230 | +1.330 | 可解 |
| QF1-2→3 | +1.508 | 2.223 | +1.899 | 可解 |

**无解段的共同特征：设计水位要求水面涨得很多，而这个河段能提供的沿程损失很小。**
水面涨得多，是因为相邻两断面的"正常水深"差得远——**几何差得远**：

- DHC1-1→2：过水面积 202.5 → 167.5 m²、顶宽 **87.7 → 54.8 m**，
  河底抬升 1.58 m。水面却要涨 2.24 m，而该段只有 0.71 m 的损失可用。
- TYSQ1-2→3：过水面积 **34.7 → 195.7 m²（差 5.6 倍）**，水面要涨 3.51 m。

### 5.2 ⚠ 我上次的"比降不自洽"假设 —— **被实测否定了**

我 10-09 判断"根因是参数比降与水面比降不一致"。这次把比降换成
**界面「按纵断面推算比降」的 jc 值**逐一复算：

| 线 | 比降 | 无解段 修好 / 弄坏 |
|---|---|---|
| BJC1 | 0.01231 → 0.01684 | **修好 1 段**（BJC1-1→2） |
| XLC4 | 0.03808 → 0.03410 | **弄坏 1 段**（XLC4-3→2 由可解变无解） |
| DHC1 | 0.00636 → 0.00978 | 仍无解（f_min +0.87→+0.57） |
| TYSQ1 | 0.01389 → 0.01350 | 仍无解（3 段一个没少） |
| CX1 | 0.00409 → 0.00639 | 仍可解 |

**净结果：无解段 7 → 7，一段没少，只是换了位置。**

⇒ **改比降只是把失败"挪个地方"，治不了根。**
上次那条判断要**收回**：根因不是比降数值，而是**"用逐断面正常水深当水面线"这个方法本身**。

### 关于根因下一步

`design_level` 的语义是"该断面的正常水深"，**它不是水面线**。
把它直接当水面线用，只要相邻断面几何差得多就不自洽——这与比降取值无关（§5.2 已证）。

要往前走，得先在这两条里选一条：

**路线 A（推荐）：让水面线由推算决定，而不是由曲线决定。**
给一个**边界条件**（下游断面的正常水深，或用户指定水位），
然后**沿能量方程往上推**，**推出来的水位就是这条线的水面线**。
逐断面 `design_level` 只用于成灾水位/淹没范围等单断面口径，不再当纵剖面输入。
——这才是 HEC-RAS 的做法，也才能真正落地 §6.7。

**路线 B：承认这是"多级跌水"河道，按控制断面分段。**
AL1、MFG1 这类（河底单段抬升 10 m 以上）本就是跌水，
应按跌水位置拆成独立河段，每段设自己的边界。

**验证前提**：无论走哪条，先用一个小算例把判据钉死——
拿一条几何渐变的合成河道，看"路线 A"能否把 23 段全部算通。
能，再动真数据。
