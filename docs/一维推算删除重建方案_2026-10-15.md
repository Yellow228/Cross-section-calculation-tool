# 一维推算（hydro1d）代码删除与重建方案

> 日期：2026-10-15　｜　性质：**方案，未动手删**（等你确认后再执行）
> 目标：把现有"一维推算"全部代码标注并删除，推倒重来。

---

## 一、结论

现有的一维推算（`hydro1d.py` + 它的全部调用链）**已确认根因性缺陷**（详见
`docs/混合流实现审查_2026-10-13.md`）：混合流比力合并判据物理错误、缺控制断面机制、
起推水位用外插的 design_level。**修修补补不划算，推倒重来是对的。**

好消息是：一维推算在整个代码库里是**边界清晰、可整体摘除**的一块——
它是"单断面 H~Q 计算"（rating 链路）**之外**附加的"纵剖面水面线推算"，
摘除后 `rating.py` 反而成为唯一水力链路，之前反复强调的
"三条链路糙率同口径"问题**自动消失**（因为只剩一条了）。

---

## 二、现状全景（依赖图）

一维推算的代码分布在 **11 个源文件 + 4 个测试文件**，但边界很清晰：

```
hydro1d.py（核心，整文件删）
   ├─ solver.solve_profile_line ── main_window（重新计算时调用）
   ├─ model.ProfileLine（4 字段：enabled/regime/levels/nodes）
   ├─ model.Section（2 字段：hydro_loss_contraction/expansion）
   ├─ config（2 字段：kinetic_alpha / kinetic_alpha_auto）
   ├─ project_io（序列化上述 6 个字段）
   ├─ exporter（3 个导出函数 + 3 个导出选项）
   ├─ dialogs（Hydro1DDialog + HydroLossDialog + α 控件 + 导出勾选框）
   ├─ main_window（菜单 2 项 + 调用 + hydro_warnings + 视图传参）
   ├─ profile_view（画"一维推算水面线"）
   └─ section_view（画"一维推算水面线"）+ canvas_base（COLOR_HYDRO1D）

共用代码（**保留**）：
   slope.estimate_line_slope  ← 也被「按纵断面推算比降」面板用，是独立功能
   geom.section_geom / surface_span / wetted_polygons  ← 被 rating 与视图共用
   rating / terrain / interp / chainage / spatial  ← 与一维推算无关
```

**关键判断**：`zone_conductance`、`get_node_state`、`HydroNode`、`compute_critical_depth`、
`compute_normal_depth`、`standard_step_method_*`、`calculate_specific_force`、
`_secant_detail`、`_bisect_detail` —— 这些**全部只在 hydro1d.py 内部互相调用**，
`rating.py` 并不 import 它们（rating 自己算分区 Q）。所以删 `hydro1d.py` 不会破坏 rating。

## 六、版本与兼容性

1. **版本号**：这是一次**删除用户可见功能**的改动。按语义化版本，删除功能属于
   **主版本 +1**（破坏性）或至少 **次版本 +1**。建议 **1.7.0 → 2.0.0**，
   或与"重建"合并成一个大版本。CHANGELOG 头同步。

2. **工程文件兼容（project_io）**：删掉字段后，`dict_to_project` 只读它认识的键，
   旧工程文件里多余的 `hydro1d_enabled`/`hydro1d_regime`/`hydro_loss_*` 键会被
   **静默忽略**——旧文件仍能打开，只是这些设置失效。这是"删除功能"的正常表现，
   无需 bump `FORMAT_VERSION`（版本号是防"旧程序读新文件丢数据"，反向不涉及）。

3. **`Any` import 清理**：`model.py` 的 `Any` 是上一轮为 `hydro1d_nodes` 补的，
   删字段后确认无其它使用则回退。

## 七、重建方向（推倒重来后怎么做，简要）

基于前几轮审查的定论，重建要守住两条：

1. **`design_level`（正常水深）不是水面线**。新的一维推算必须**给边界条件
   （下游正常水深或用户指定水位），沿能量方程往上游推**，推出来的才是水面线。
   `design_level` 只用于单断面口径（成灾水位、淹没范围）。

2. **控制断面 + 分段求解**：逐断面算临界水深，找出控制断面（水跃/跌水），
   以之为界切分子段，各段纯缓/纯急独立解，段间用**共轭水深（比力守恒）**定位水跃，
   而不是"单断面比力大小"。

**建议重建的模块边界**（新文件，不再叫 hydro1d.py，避免历史包袱）：
- `src/core/profile_routing.py`：水面线推算主入口（`compute_profile`）；
- `src/core/control_section.py`：临界水深 / 控制断面识别；
- `src/core/step.py`：标准步长法单步（缓流/急流），求根不收敛返回 NaN 不伪造。

**硬性前提**：动手前先写**解析水跃算例**（矩形宽渠，跃后水深有共轭水深解析解），
把"代码输出 vs 解析解"做成回归测试、先让它失败，再写实现——专防"测试不看数值"。

（重建细节另立方案，本方案只负责"删干净 + 定边界"。）
