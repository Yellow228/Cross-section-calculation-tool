## 二、要处理的问题

### 问题 1（建议删）：机器人把 5 个"改代码脚本"提交进了 `tools/`

```
tools/add_export_all_table.py
tools/add_export_checkbox.py
tools/add_export_hydro1d_table.py
tools/fix_hydronode.py
tools/update_hydro1d_profile.py
```

这些**不是工具**，是机器人用来对源码做字符串替换的一次性补丁脚本
（`content.replace(search, replace)` 然后写回）。两个实证问题：

**① 不幂等 —— 再跑一次会损坏源码。** 实测 `add_export_checkbox.py` 的
`search` 串在改动落地之后**仍然匹配**（那两行 `hydro1d` / `hydro1d_range`
还在原位），所以再执行一次会往字典里**重复插入 `hydro1d_table` 键**：

```
重跑 add_export_checkbox.py 的 search 串是否仍能匹配: True
改完后已有的键: ['hydro1d', 'hydro1d_range', 'hydro1d_table']
!! 危险：再跑一次会重复插入 hydro1d_table
```
Python 的重复字典键**不报错**（后者覆盖前者），属于静默出错。

**② 有的脚本从一开始就没生效。** `add_export_all_table.py` 里写的搜索串是
```
'hydro1d': 一维推算水面线.csv
```
而真实源码是 `'hydro1d': True,` —— `str.replace` 找不到就**静默什么都不做**，
脚本照样正常退出。这正好是"看着干完了，其实没干"的典型。

**建议：整批删掉这 5 个文件。** 它们不是可复用工具，留着既误导后人，又有被误跑的风险。

### 问题 3（留意）：`compute_hydro1d_profile` 发生了**破坏性 API 变更**

```python
# 旧
-> list[float]
# 新
-> tuple[list[float], list['HydroNode']]
```

- `src/core/solver.py` 已同步（解包成 `line.hydro1d_levels, line.hydro1d_nodes`）✓
- `tests/` 不受影响（两个调用点都忽略返回值）✓
- **但这是对外的破坏性变更**：任何别的调用方拿到 tuple 当 list 用就会出错。

另外 `model.py` 新增的字段用了 `Any` 却**只 import 了 `Optional`**：
```python
from typing import Optional          # ← 没有 Any
...
hydro1d_nodes: list[Any] = ...
```
目前靠 `from __future__ import annotations`（注解不求值）侥幸不报错，
一旦有人调用 `typing.get_type_hints()` 就会 `NameError`。建议补上 import。

### 问题 4（**订正：我初版报告写重了，此处收回**）

初版我用**合成断面**看到 "n=0.1 时上游 10.2444 < 下游 10.2587 且零告警"，
一度把它当成"还没被覆盖的静默失败"。**换真实数据复测后，这个定性站不住，特此收回。**

真实数据结果（8 条线，强制启用一维推算）——共 9 处"上游水位低于相邻下游断面"：

| 线 | 反常处 | 幅度 | 告警 |
|---|---|---|---|
| sls2-段1 | 2 处 | **12 cm** | ✅ 有（越临界 + 贴边） |
| xlc7-段2 | 1 处 | **67 cm** | ✅ 有（越临界 + 贴边） |
| yqc6 | 1 处 | **7 cm** | ✅ 有（越临界 + 贴边） |
| sls2-段2 | 2 处 | 0.02 ~ 0.2 mm | ❌ 无 |
| sls2-段3 | 1 处 | 0.2 mm | ❌ 无 |
| ypc6 | 1 处 | 1 mm | ❌ 无 |
| xlc7-段1 | 1 处 | 2.5 mm | ❌ 无 |

规律很清楚：**幅度 > 1 cm 的全都带告警；零告警的那几处幅度都在 0.2~4 mm**。
而二分法的残差容差是 `tol = 1e-4 m`（0.1 mm，见 `_bisect_detail` 的调用处），
所以这些"零告警的反常"是**求解器容差量级的数值噪声**，不是物理反常。

**结论：这不是静默失败。** 真实数据上，物理上真正可疑的那些（厘米级以上）
都已经被告警覆盖到了——PR #14/#15 补的诊断通道是有效的。

唯一还值得提的是**措辞**：既然 PR #17 把 `Z_up = Z_crit` 加回来了，
越临界时导出的 `Z` 实际**等于 `Z_crit` 而不是能量方程的解**，
但告警只说"结果仅供参考"，没说明"这个数字被替换过"，读者可能以为那是算出来的值。
