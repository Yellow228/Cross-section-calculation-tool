## 一、结论（先给）

**这次是认真的、方向正确的重写。上一版一维推算的三个根因全部修掉了。**

上一版被删除的三个根因，对照这次：

| 上一版根因 | 这次怎么修的 | 状态 |
|---|---|---|
| 混合流比力合并判据物理错误（单断面比 M 大小） | `profile.py::_merge_mixed` 用 HEC-RAS 混合流算法：亚临界遍自下游 + 超临界遍自上游，自上游向下游比力大者控制，亚临界比力反超→水跃 | ✅ 修复 |
| 缺控制断面机制（两遍独立推、失败 NaN 级联） | 逐断面临界水深校核 + 不收敛回退临界（有告警）+ mixed 两遍比力合并 | ✅ 修复 |
| 起推水位用 design_level 外插（可高于岸顶） | 边界条件显式化：`ws`/`critical`/`normal`/`rating`，默认**正常水深**（曼宁公式，天然落在有效区间） | ✅ 修复 |

**数值正确性有扎实的解析算例验证**（25 个测试全过，误差 mm 级）——这正是上一版缺失、也是我上次明确要求补上的东西。

**三腿全绿**，真实工程上**不再有 NaN 断层**（上一版 TYSQ1 有 7/8 断面 NaN）。

## 二、新引擎做了什么（`src/raslite/`，约 1100 行）

| 模块 | 职责 | 关键点 |
|---|---|---|
| `geometry.py` | 断面几何与水力属性 | 分区糙率、`alpha=At²Σ(Kᵢ³/Aᵢ²)/Kt³`（式2-11）、堤防、半湿段、`y_centroid` 形心压强头 |
| `hydraulics.py` | 临界/正常水深、比力 | 临界用**比能最小法**（secant 30 片，非 Fr²=1 求根）、正常水深曼宁二分、比力 `SF=αQ²/(gA)+A·ȳ` |
| `profile.py` | 标准步长法主流程 | 能量方程、流量加权长度（式2-3）、4 种摩阻坡度、**HEC-RAS 迭代策略**（投影→0.7×误差→割线法）、混合流两遍+比力合并 |
| `network.py` | 河网（Reach+Junction） | 亚临界汇合口（reach by reach energy balance） |

**几个对得上的关键细节**（说明作者真读过 HEC-RAS 参考手册）：

1. **迭代策略**：试值1=上一断面水深投影、试值2=假定值+0.70×误差、试值3+=割线法外推（式2-18）、容差 0.003m=0.01ft。逐字对齐 HEC-RAS 计算流程。
2. **临界水深用比能最小法**而非 Fr²=1 求根——代码注释明确写了"复式断面 α 随水位变化时 Fr²≠1，两种方法差可达 1m"，这是上一版没意识到的问题。
3. **收缩/扩张判定**：`hv_ds > hv_us → 收缩`（下游流速水头大→收缩），与上一版 PR #23 修的方向一致，这次写对了。
4. **混合流 `_merge_mixed`**：自上游向下游，超临界解比力大者控制；亚临界比力反超→水跃判定；亚临界区遇"默认临界"断面→转回超临界。这是 HEC-RAS 混合流算法的正确形态，**彻底替换了上一版"单断面比 M 大小"的错误判据**。

`tests/raslite/run_all.py` 用**解析算例**锁正确结果（正是上一版缺失的）：

## 四、真实工程实测（`危险区8个百年一遇.dmprj`）

**进步**：上一版 TYSQ1 有 7/8 断面 NaN、DHC1 2/3 NaN；这次**全部无 NaN 断层**。混合流模式的 Fr 分布也不再出现上一版"水跃下游急流"的物理错误。

**遗留问题**（这是诚实、可接受的兜底，不是 bug）：

真实工程上仍大量断面"**迭代 40 次未收敛 → 默认取临界水深**"：

| 线 | subcritical 默认临界 | mixed 默认临界 |
|---|---|---|
| AL1 | 2/3 | **1/3** |
| MFG1 | 2/4 | **1/4** |
| QF1 | 2/3 | **1/3** |
| TYSQ1 | 7/8 | **6/8** |

`mixed` 模式**显著减少**了兜底（两遍各推一次、取更合理的一侧）。但兜底仍存在。

**原因**：这是我在 10-09 就定位的同一件事——那份工程的**相邻断面几何突变**（渠底单段爬升 5~12 m，如 MFG1-1→2 爬 12.45 m）导致能量方程在该段**无解**。这不是引擎能修的，是数据本身。区别在于：上一版是**静默**钳到临界，这一版是**明确告警 + `defaulted_critical` 标记 + 导出 CSV 标注 "Defaulted Critical"**——诚实了。

## 五、遗留问题清单（按严重度）

### P2 —— 建议修

1. **版本没 bump**：新增了用户可见功能（RASlite 一维推算引擎），`VERSION` 仍是 `2.0.0`，应 → **2.1.0** 并补 CHANGELOG。（这是机器人 PR 反复出现的老毛病，第 4 次了。）

2. **`ProfileLine.hydro_config` 未声明在 dataclass**：`model.py` 只新增了 `HydroConfig`/`HydroResult` 两个 dataclass，但 `ProfileLine` **没有** `hydro_config` 字段。代码用 `hasattr(line, "hydro_config")` + `line.hydro_config = ...` 动态赋值（`main_window.py`、`project_io.py`）。dataclass 默认无 `__slots__` 所以不崩，但**不严谨**——新 `ProfileLine()` 访问 `hydro_config` 会 AttributeError，且字段不入 `dataclasses.fields()`、不进 repr/eq。应在 `ProfileLine` 里显式声明 `hydro_config: Optional[HydroConfig] = None`。

3. **测试脚本 import 路径**：`tests/raslite/run_all.py` 的 docstring 写"直接 python 运行"，但 `python tests/raslite/run_all.py` 会 `ModuleNotFoundError: No module named 'src'`（它 `sys.path.insert` 的是 `src/` 却 `from src.raslite import`）。**必须用 `python -m tests.raslite.run_all`**。要么改 docstring，要么改 import 路径。

4. **exporter 里 `except Exception: pass` 静默吞掉导出失败**：`export_all` 里 `export_hydro_csv` 那段的 try/except 什么都不做，一维推算导出失败时用户完全不知道缺了文件。应至少记一条 warning 或提示。

### P3 —— 观察项

5. **`reach_lengths` 三段等长**：`core/hydro1d.py::_to_cross_section` 把 LOB/CH/ROB 三段距离都设为 `(dist_ds, dist_ds, dist_ds)`。真实工程没有分段长度数据，退化成等长——这会让流量加权长度（式2-3）退化成简单距离。可接受，但值得在文档里说明局限。

6. **导出选项默认勾选**：`export_all` 里 `options.get('hydro1d', True)` 默认 True，会对每条线**重新跑一遍一维推算**再导出——即使用户从没打开过一维推算面板。这会把"默认临界"的兜底结果也导出。建议默认不勾，或复用界面已算好的缓存结果。

## 六、总体评价

**这是一次合格的推倒重来**：上一版三个根因全修、算法对齐 HEC-RAS、数值有解析算例背书、三腿全绿。

**唯一需要警惕的**：真实工程上"默认取临界水深"的兜底仍然很多。这是数据问题（几何突变），不是引擎问题——但用户看到"算出来 Fr=1.00 一片"时可能误以为是引擎坏了。建议在界面上把 `defaulted_critical` 显式标出来（现在导出 CSV 有 "Defaulted Critical" 字样，但界面上可能不够醒目）。

**建议动作**（按优先级）：
1. bump 版本到 2.1.0 + 补 CHANGELOG（第 1 条）；
2. `ProfileLine` 显式声明 `hydro_config` 字段（第 2 条）；
3. 修测试脚本 import 路径 / docstring（第 3 条）；
4. exporter 的静默 `except` 改成显式提示（第 4 条）。
