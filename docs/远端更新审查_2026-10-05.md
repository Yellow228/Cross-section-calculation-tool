## 二、必须修的问题

### 问题 1（较严重）：导出→导入一轮，主槽糙率被静默改掉

导出表头是 `横断面名称, 设计流量, 糙率, 左岸糙率, 右岸糙率`——**没有「主槽糙率」列**。
但导入代码里明确写着：

```python
if p.roughness_left is None and p.roughness_right is None:
    p.roughness_main = None
else:
    p.roughness_main = p.roughness   # ← 无条件被统一糙率覆盖
```

实测（我复刻了两端逻辑跑通）：

```
A: before = (Q=120, n=0.035, n_main=0.030, n_L=0.040, n_R=0.045)
   after  = (Q=120, n=0.035, n_main=0.035, n_L=0.040, n_R=0.045)
   !! 变化字段: ['roughness_main']        ← 0.030 被改成 0.035
```

**用户什么都没改，只是「导出再导入」，主槽糙率就变了**，而且状态栏只报「更新了 N 个断面」，不会提任何字段被改。这正好落在项目最忌讳的「静默失败」类别里。

**建议**：导出补上「主槽糙率」列（共 6 列）；导入只在 CSV 真的提供了该列时才写 `roughness_main`。

### 问题 2（较严重）：非法数字静默变成 NaN，不留痕

`parse_val` 解析失败返回 `nan` 且**不计数、不报错**：

```python
except ValueError:
    return float("nan")
```

实测会被判成 NaN 的输入（都是常见手误）：

| 输入 | 结果 |
|---|---|
| `120 m3/s`（带单位） | NaN，静默清空 |
| `1,200`（千分位） | NaN，静默清空 |
| `0.035。`（中文句号） | NaN，静默清空 |
| `－0.001`（全角负号） | NaN，静默清空 |
| `1.2e2` / `１２０`（全角） | 正常解析 |

危害不只是「值丢了」：**设计流量一旦变 NaN，`hydro1d.py:390` 会静默用 50.0 代替**继续算，于是出一份看起来很正常的错水位，全程无告警。

对比一下：项目里 `reader.py` 载入 Excel 时对解析失败是**会写进 warnings 并提示用户**的。这里应该同样处理——建议解析失败的行**跳过并计数**，结束后在状态栏/消息框里明确列出「第 N 行 xxx 无法解析，已跳过」，不要静默写 NaN。

## 三、顺带发现的一个既有 bug（与本次 PR 无关）

**位置**：`src/core/hydro1d.py:427` 与 `:467` —— `res_levels[i] = max(Z_up, Z_crit)`
**引入时间**：PR #1 `e31d4b7`（1D 水动力功能最初引入时就有，v1.4.0 起一直在）

**现象**：糙率变大时，下游水位正常抬高，但**上游水位被钉死不动**，于是出现「上游水位低于下游」的反常水面线。

实测（三段河床缓降、几何相同、只改糙率）：

```
n=0.03   S1=8.9557  S2=8.8064  S3=8.8922
n=0.04   S1=8.9557  S2=9.1046  S3=9.1423   ← S1 居然低于下游 S3
n=0.10   S1=8.9557  S2=10.2536 S3=10.2587
```

**根因**（已用探针定位，不是猜测）：`Z_crit` 是临界水位，只依赖几何与流量、**与糙率无关**。实测 S1 的 `Z_crit = 8.955674` 恒定不变，恰好等于被冻结的那个值。能量方程解 `Z_up` 本身是随糙率变化的（8.806 / 9.105 / 9.555 / 10.254），但 `max(Z_up, Z_crit)` 把它钳在 `Z_crit` 上，于是水位定格在临界水位。

**风险**：在缓流里用 `max(·, Z_crit)` 强制抬到临界水位，物理上是可疑的——缓流水深应大于临界水深，但这个「抬升」在最上游断面会让水面线**失去单调性**，用户拿到的纵断面图是错的，且程序不会报错。

（本次我只做了只读定位与复现，没有改代码——修法需要你定：是去掉该钳位、还是钳位后补告警，属于水位推算口径的决策。）
