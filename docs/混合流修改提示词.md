### 已确认的三个问题（审查结论，直接采信，不用重新验证）

1. **【P0 致命】比力合并判据错误**。当前代码：

   ```python
   if M_sub >= M_sup:
       res_levels[i] = z_sub      # 取缓流
   else:
       res_levels[i] = z_sup      # 取急流
   ```

   比力 `M(h) = A·ȳ + Q²/(gA)` 是水深 h 的 **U 形曲线**：急流区（h < 临界水深）
   单调递减、缓流区（h > 临界水深）单调递增，最低点在临界水深。因此 **M 的大小
   不区分流态方向**——急流(0.2 m) 的 M 可以高达 127，缓流(1.5 m) 的 M 却只有 28。
   这个"单断面比 M 大小"的规则没有物理意义，会选错边。
   **正确判据是断面之间的比力守恒（共轭水深）`M(上游)=M(下游)` 来定位水跃位置。**

2. **【P1】框架缺"控制断面"机制**。HEC-RAS 混合流的正确做法是：
   逐断面算临界水深 → 找出**控制断面**（临界水深位置：水跃、跌水等）→
   以控制断面为界**把河段切成若干子段** → 每个子段内部是纯缓流或纯急流独立求解 →
   子段之间用比力守恒衔接。
   当前代码是"缓流推一遍 + 急流推一遍 + 在失败处硬拼"，遇到第一个无解的段就停
   （后续全 NaN），没有控制断面的概念。实测一个必然产生水跃的算例（陡坡→缓坡）
   结果水位线 `11.219 / NaN / 7.109 / 5.719`——中间断掉，且水跃下游居然出现急流，
   物理不自洽。

3. **【P1】起推水位用 `design_level`，没用正常水深当边界**。`design_level` 由
   H~Q 曲线外插得到，可能高于岸顶、且相邻断面正常水深之间不自洽。正常水深函数
   `compute_normal_depth` 已经存在，但目前只在 design_level 为 NaN 时兜底，
   **语义没落地**。

### 附带的小问题（止血时一并处理）

4. **【P2】`_secant_detail` 的 docstring 撒谎**：写"不收敛时回退临界水深"，实际
